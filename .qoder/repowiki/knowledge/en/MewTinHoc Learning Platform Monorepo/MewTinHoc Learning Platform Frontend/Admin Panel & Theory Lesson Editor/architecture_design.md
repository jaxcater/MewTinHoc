Three sibling React components under `src/components/` forming the admin surface:
- `AdminPage.jsx` is the root dashboard: it gates access via `isCompanyAdmin(currentUser)` from `../lib/roleService.js`, fetches `profiles` rows directly through the `supabase` client (`../supabase.js`), renders metric cards, a searchable table, an inline SQL guide (with a copy-to-clipboard snippet that creates the `profiles` table, RLS policies, and storage policies for bucket `KhoTaiLieuTinHocThiThu`), a storage-write diagnostic via `testRoadmapStorageWrite()`, and embeds `AdminAnnouncementsPanel`.
- `AdminAnnouncementsPanel.jsx` is a self-contained CRUD panel for announcements; it delegates all persistence to `../lib/announcementService.js` (`fetchAllAnnouncements`, `createAnnouncement`, `setAnnouncementActive`, `deleteAnnouncement`) and exposes constants `ANNOUNCEMENT_TYPES`, `ANNOUNCEMENT_LIMITS`, `ANNOUNCEMENTS_SQL` for the schema bootstrap UI.
- `AdminTheoryEditor.jsx` is a stateless-ish form component exported as both default and named helpers (`buildLessonDraft`, `applyDraftToLesson`). It owns a local `draft` state derived from the incoming `lesson` prop, provides incremental `patch`/`updateSection`/`updateQuizOption` updaters, and returns a fully transformed lesson object to the parent's `onSave` callback — no direct DB calls inside this file.

Dependency direction is one-way: AdminPage → AnnouncementsPanel (imported) and AdminPage → external libs (supabase, roleService, roadmapStorage); AdminTheoryEditor has no internal dependencies beyond lucide-react icons. All three components use inline JSX styles rather than a CSS framework.
